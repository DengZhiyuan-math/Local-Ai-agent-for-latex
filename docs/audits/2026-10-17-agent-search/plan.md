# agent 辅助的搜索替换：方案

日期：2026-10-17。来源：你说需要"更高级的搜索模式，在 agent 的辅助下完成更复杂的搜索，比如批量把某个下标 i 换成 j，或者批量更新记号"。执行结果写入同目录的 `report.md`。

## 为什么普通的查找替换不够

- "下标 i 换成 j"：`x_i`、`a_{ik}`、`\sum_{i=1}^n` 里的 i 要换；`\int`、`\in`、`i.e.`、正文里的 "i" 不能换。正则写起来难，而且只该在公式里生效。
- "更新记号"：`\mathcal{O}_X` 改 `\mathscr{O}_X`，`\langle x, y\rangle` 改 `\inner{x}{y}`：要分组、要看上下文，有的地方还得判断是不是同一个对象。

这些需要理解内容，但改动本身必须逐处可见、可选、可撤回。

## 做法：agent 提议，你审阅，Prism 应用

1. 在全项目搜索面板里加一个模式 **Ask the agent**（与 Find 并列的两个标签）。你用一句话描述要改什么。
2. Prism 用当前 agent（聊天面板里选的那个：Claude Code、Codex、Deep Code 或 API）跑一轮 **Ask（只读）** 的新会话：agent 可以读、搜项目，但不能改任何文件。这一轮不进聊天记录，面板里显示进度和 Stop。
3. agent 的回答是一个固定格式的块（`prism-search`），里面有：
   - **规则**（首选）：JavaScript 正则、替换文本（可用 `$1`）、作用范围（只在公式里 / 只在正文里 / 任何地方）、是否区分大小写、一句说明；
   - **逐处修改**（规则写不出的情况）：文件、行号、该行里要换的原文、新文字、一句说明；
   - 一段总结。
4. Prism 自己执行规则，在项目里找出每一处命中；逐处修改要核对原文确实在那一行。所有改动按文件列出，每处显示改前、改后（差异着色）、复选框；默认全选。
5. 规则在面板里**可以直接改**（正则、替换、范围），改完立即重新预览。不必再问 agent。
6. **Apply** 应用勾选的改动，与全项目替换相同：打开的文件在标签页里改（可 ⌘Z），其他文件写回磁盘，期间被改过的文件不写并列出。
7. agent 的回答读不懂、规则不是合法正则、某处修改对不上原文时，用一句白话说明，原文放在 Details 里，其余能用的照常预览。

## 公式范围（`findlogic.js` 新增 `regions`）

把一个 LaTeX 文件分成三类区间：注释、公式、正文。公式：`$…$`、`$$…$$`、`\(…\)`、`\[…\]`，以及 equation、align、alignat、flalign、gather、multline、eqnarray、math、displaymath（含 `*`）环境。`\$` 不算公式开始。"只在公式里"的规则，命中必须整个落在一个公式区间内；"只在正文里"的，不能碰公式和注释；"任何地方"不限。

## 给 agent 的说明（`agentsearch.js` 生成）

- 你的请求原文；项目的主文件和文档文件列表；
- 回答格式，以及要求：优先用规则；规则用 JavaScript 正则语法，在 JSON 里反斜杠要写两次；尽量收窄，宁可漏掉让人补，也不要误伤；先在文件里核对规则命中的是对的；规则覆盖不了的才逐处列出；不要改文件；
- 用你的语言写说明和总结。

## 测试

- Node（`frontend_check.js`）：`regions` 的各类公式和注释、`\$`；回答的解析（找最后一个 `prism-search` 块、JSON 错误、字段缺失、非法正则）；规则在三种范围下的命中；逐处修改的核对（行号对不上、原文在行里出现多次）；命中重叠时只留一个。
- 浏览器：假的 API 返回一个准备好的回答。检查：面板显示进度，回答到达后列出命中；取消一处后 Apply 只改其余的；在面板里改规则后预览更新；打开的文件 ⌘Z 一次撤回；回答格式错时的说明。
- 真实 agent（Claude Code）在 examples 的副本上跑一次"把下标 i 换成 j"，记录结果，不计入自动回归。

## 顺序

```
8.1 regions + 规则命中（findlogic.js）
8.2 agentsearch.js：说明文字、回答解析、命中合并
8.3 面板：Ask the agent 模式、进度、预览、应用（应用与全项目替换共用一段代码）
8.4 测试用的假 API 返回准备好的回答；浏览器测试
8.5 README；真实 agent 试一次；回归；report.md
```

## 不做

- 让 agent 直接改文件（那是聊天面板的 Edit 模式，已有）。
- 对预览中的每一处再请 agent 复核（以后可以加一个"请 agent 检查选中的几处"）。
