# Domain docs

This repository uses a single domain context.

Before exploring:
- Read CONTEXT.md for the project's domain vocabulary.
- Read relevant decisions in docs/adr/ when present.

Use the glossary's terminology consistently.
Keep CONTEXT.md focused on domain terms, not implementation plans.

If a relevant document does not exist, proceed without blocking.
Create glossary entries or ADRs only when there is substantive
domain knowledge or a qualifying architectural decision to record.

Surface conflicts with existing ADRs instead of silently overriding them.
